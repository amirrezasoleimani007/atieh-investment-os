# نسخه ۵۷ — گزارش هوشمند مستقل با Ollama محلی

این نسخه مستقل بر پایه نسخه ۵۶ است. محل انتشار فقط `financial-watch/v57/` است. صفحه اصلی و نسخه‌های قبلی مخزن تغییر نمی‌کنند. کتابچه هفتم در دیده‌بان بدون بازنویسی حفظ شده است.

## شروع ساده در ویندوز

۱. Ollama را باز نگه دارید. مدل `qwen3:4b-instruct` باید نصب باشد.

۲. بسته `Atieh57-Windows.zip` را کامل استخراج کنید؛ برنامه را از داخل ZIP اجرا نکنید.

۳. روی `Start-Report.cmd` دوبار کلیک کنید. مرورگر در `http://127.0.0.1:4177/` باز می‌شود. این رایانه به Node.js دسترسی دارد؛ برای رایانه دیگر Node.js نسخه 22.13 یا جدیدتر از nodejs.org لازم است. نصب وابستگی‌های npm برای بسته اجرایی لازم نیست.

۴. داده‌های سامانه را مثل قبل بارگذاری کنید. از نوار اصلی وارد «گزارش هوشمند» شوید، شرکت، دوره و منابع شواهد را انتخاب و «تولید گزارش هوشمند» را بزنید. تا پایان تولید، منابع را تغییر ندهید. تغییر انتخاب‌ها، درخواست و متن قدیمی را پاک می‌کند.

این بار متن واقعاً با مدل محلی تولید می‌شود؛ قالب آماده یا گزارش نمونه جای پاسخ هوش مصنوعی نمایش داده نمی‌شود. خروجی چهار پاراگراف دارد و امکان کپی، دریافت متن، JSON گزارش و شواهد، و چاپ فراهم است. شواهد هر بند و تاریخ ورود هر منبع قابل مشاهده‌اند. سرعت به سخت‌افزار و حجم منابع منتخب وابسته است؛ سقف انتظار بیست دقیقه است و امکان لغو وجود دارد.

نسخه عمومی GitHub Pages رابط را نمایش می‌دهد، اما برای اتصال به Ollama همین رایانه باید بسته محلی اجرا شود. نیازی به دستکاری CORS، تنظیمات مرورگر، VPN یا کلید API نیست. بسته شامل مدل نیست؛ از مدل نصب‌شده روی رایانه استفاده می‌کند.

## منابع مستقل انتخابی

- ارقام واقعی مالی با واحد منبع، دوره مشابه قبل، تاریخچه منتخب و میانه همتایان هم‌دوره و هم‌ماهیت؛ شرکت منتخب از مرجع حذف می‌شود و حداقل دو همتای دیگر لازم است.
- هشت محور دیده‌بان، رتبه‌نما با وزن‌های پایه و سرمایه/ارزش‌آفرینی موتور موجود سامانه؛ این‌ها داده مستقل چندباره نیستند.
- پایش تطبیقی عملکرد، با گروه همتای فایل پایش و مقایسه سال‌های متوالی منتخب.
- تولید و ظرفیت، سود محصولات و بودجه، ارزیابی بازار، دارایی، فعالیت و تجهیزات متیل.

داده سالانه محصول، تولید و پایش به گزارش شش‌ماهه تبدیل نمی‌شود. منابع فاقد شاهد در همان دوره با سال دیگری پر نمی‌شوند. سال‌های برنامه تولید، در گزارش ترکیبی مبنای «آخرین عملکرد» را از داده واقعی جلو نمی‌برند. بودجه آینده با برچسب برنامه وارد می‌شود. داده بازار، دارایی و تجهیزات فاقد تاریخ مالی، فقط تصویر مقطعی هستند؛ زمان ورود فایل با دوره مالی تفاوت دارد. ارزش دفتری، ارزش روز نیست و ظرفیت، تولید محقق‌شده نیست.

جدول شواهد ورودی در بخش جمع‌شونده قابل بررسی است. برای محدود نگه‌داشتن ورودی مدل کوچک، جزئیات حداکثر پنج خط تولید، سه محصول اصلی، شش طبقه دارایی، شش گروه فعالیت و پنج عملیات تجهیزات وارد می‌شود. این گزارش جای بررسی تمام ردیف‌های دفتر مالی نیست. در فایل محصول، جمع کل و جزئیات با هم جمع نمی‌شوند؛ مقادیر مفقود صفر فرض نمی‌شوند. داده‌های متیل و آتیه با قواعد تطبیق نام و هلدینگ جدا می‌مانند.

## حریم اطلاعات و کنترل پاسخ

مرورگر خلاصه منابع انتخابی را به سرور loopback همین رایانه می‌دهد و سرور فقط با `127.0.0.1:11434` ارتباط می‌گیرد. آدرس سرویس مدل از داخل رابط قابل تغییر نیست؛ مدل‌های cloud پذیرفته نمی‌شوند. نام شرکت، نام فایل و ردیف‌های خام اکسل در بسته مدل نیستند؛ نام محصول و برچسب‌های شاخص‌های منتخب ممکن است در خلاصه باشند. هیچ فراخوانی OpenRouter در این مسیر انجام نمی‌شود. فایل‌های مالی، شواهد واقعی و خروجی‌های آزمایش در انتشار عمومی نیستند.

خروجی JSON Schema دارد. چهار بند، شناسه شواهد، ارجاع‌ها و اعداد مستقل کنترل می‌شوند؛ اعداد در متن باید در شواهد ارجاع‌شده همان بند یا دوره گزارش وجود داشته باشند. متن HTML اجرا نمی‌شود. خطا، قطع اتصال، لغو یا پاسخ ناقص به‌عنوان گزارش موفق نمایش داده نمی‌شود. این کنترل‌ها صحت تمام تفسیرهای مدل کوچک را تضمین نمی‌کنند؛ متن قبل از استفاده مدیریتی بازبینی شود.

این بسته برای اجرای محلی یک کاربر است. سرور فقط روی loopback گوش می‌کند و فایل‌های دلخواه رایانه را سرو نمی‌کند. انتشار سازمانی چندکاربره، سرور داخلی و کنترل دسترسی جداگانه می‌خواهد.

## ساخت از سورس

```powershell
npm ci
npm test
npm run build
npm run report:serve
```

سورس کامل در `Atieh57-source.zip` است. فایل‌های پوشه `changes` فقط برای مرور تغییرات‌اند. برای اجرای آماده، از `Atieh57-Windows.zip` استفاده کنید. نتایج اعتبارسنجی این انتشار در `build-manifest.json` ثبت می‌شوند.

## ورود مستقیم به گزارش

در بالاترین قسمت صفحه اول، کارت مستقل «گزارش هوشمند عملکرد» و دکمه «ورود به گزارش هوشمند» دیده می‌شود؛ این دکمه پیش از بارگذاری هر فایلی فعال است. صفحه گزارش، عنوان و بخش بارگذاری مخصوص خودش را دارد. برای شروع، یک دیتابیس مالی معتبر یا فایل پایش تطبیقی کافی است؛ لازم نیست ابتدا وارد دیده‌بان شوید یا هر دو فایل مالی را بارگذاری کنید.

لینک مستقیم: https://amirrezasoleimani007.github.io/atieh-investment-os/financial-watch/v57/#report

فایل Start-Report.cmd نیز مستقیماً همین صفحه گزارش را در اجرای محلی باز می‌کند. از «بازگشت به سامانه» به صفحه قبلی برمی‌گردید و داده‌های واردشده حفظ می‌شوند. میانبر گزارش در نوار اصلی سامانه نیز همیشه در دسترس است.

این انتشار، دسترسی و جانمایی گزارش را تغییر می‌دهد؛ موتور تحلیل و مدل Ollama همان نسخه ۵۶ است. آزمون زنده مدل ذکرشده در راهنمای زیر، مربوط به نسخه ۵۶ است و در این انتشار دوباره اجرا نشده است.
برای مدل کم‌حجم، ورودی مدل از شواهد کلیدی هر منبع انتخاب می‌شود؛ از هر منبع دارای داده حداقل یک شاهد حفظ می‌شود. جدول کامل و بسته JSON، ورودی دقیق مدل را نیز جدا نشان می‌دهند. زمان تولید روی سخت‌افزار ضعیف ممکن است چندین دقیقه باشد.
اعتبارسنجی کد: ۷۹ آزمون موفق، چهار آزمون تاریخیِ فاقد فایل واقعی شش‌ماهه کنار گذاشته‌شده؛ TypeScript و ساخت مستقل و Pages موفق. تمام ۶۵۶۱ حالت کتابچه هفتم با منبع تطبیق دارند.

آزمون واقعی Ollama با شواهد پایش تطبیقی و سرمایه انجام شد؛ متن چهار بند تولید شد (حدود ۲۱۴ ثانیه در آزمون بازبینی‌شده). تصحیح ارجاع، شفاف‌کردن عبارت جهت فاصله منفی و تکمیل موضوع بررسی به صورت کنترل‌شده انجام و در خروجی ثبت می‌شود. این کنترل‌های محدود، جای بازبینی معنایی تمام متن را نمی‌گیرند. شواهد و متن واقعی آزمون در بسته عمومی قرار ندارند.
